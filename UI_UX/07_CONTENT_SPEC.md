# UCN CONTENT & MICROCOPY SPECIFICATION

Version: 2.0

## 1. Voice

Professional, direct, calm, useful, human. Avoid hype, corporate filler and gamified language.

## 2. Terminology

Prefer consistent domain terms:
- Project
- Research
- Opportunity
- Collaboration
- Request to Join
- Request Collaboration
- Connect
- Message
- Availability
- Proof of Work

Do not alternate between near-synonyms unless the distinction is intentional.

## 3. Buttons

Use specific verbs:
- Request to Join
- Request Collaboration
- Save Project
- View Project
- Message
- Connect
- Apply

Avoid generic `Submit`, `Click Here`, `Learn More` when a specific action is possible.

## 4. Empty states

Formula: state + context + next action.

Bad: “No data.”

Better pattern: “No saved projects yet. Save projects you want to revisit. [Discover projects]”

## 5. Errors

Formula: what happened + recovery.

Avoid blame (“You entered an invalid…”). Prefer neutral language (“Enter a valid university email.”).

## 6. Truncation

Never truncate information required for a decision. If clamped, provide a route to full content.

Recommended guidance:
- card title: 2–3 lines
- card summary: 2–4 lines depending layout
- metadata: concise, no multi-sentence metadata

## 7. Dates and deadlines

Use relative dates only when they improve comprehension and retain an exact date in the relevant detail context. Do not hide deadlines behind vague language.

## 8. Verification

Verification copy should explain what has been verified when that information is available. Do not imply that verification guarantees competence, quality or success.

## 9. Recommendation reasons

Use evidence-based phrases such as:
- Shared skill: Python
- Same department
- Shared research interest
- Works on a related project

Avoid invented claims such as “Perfect match.”

## 10. Content resilience

Design must work with long names, long university names, multi-word research areas, missing optional fields and localization growth.
